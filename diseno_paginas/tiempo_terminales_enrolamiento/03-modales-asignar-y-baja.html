Reglas

  • Personas asignables: cada opción lleva nombre + puesto · área para distinguir homónimos. Pedido: que el listado de personas asignables (o GET /api/personas) devuelva puesto vigente y área; si una persona no tiene asignación vigente se muestra sólo el nombre.
  • Texto y versión: el texto de la casilla viene de la versión vigente (Configuración → Texto de consentimiento) y se muestra con su número; si es provisional, con esa marca. Siempre hay una versión (la 1 se siembra como provisional): no existe «sin texto». Al asignar, el cliente manda consentimiento_id y el servidor lo guarda en una columna de la bitácora; si ya no es el vigente, siempre rechaza con 409 y la UI pide releer (estado «texto desactualizado»).
  • Consentimiento: casilla obligatoria, sin marcar por defecto; "Asignar" no se bloquea: al enviar sin marcar muestra el error del campo (así el motivo se entiende, en vez de un botón gris sin explicación).
  • Auto-asignación: aviso informativo, no bloqueo en cliente — el frontend no sabe si el caller es administrador genérico; decide el backend (422). El 422 se muestra con su detail.
  • Baja: el botón principal dice la consecuencia ("Cancelar el alta" / "Dar de baja definitivamente"), no "Aceptar". Motivo opcional ≤ 500.
  • Mientras envía: botones inertes, Esc y fondo no cierran (sin doble envío).
